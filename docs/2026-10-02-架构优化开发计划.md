# PT-depiler 架构优化开发计划

## 1. 计划基线

本计划将[架构优化方案](./2026-09-30-架构优化方案.md)拆为可独立提交、评审和验收的剩余开发任务。设计约束、数据策略和最终验收口径以原方案为准；本计划不替代原方案第 10 节的 AO-01～AO-13 进度记录。

| 项目     | 内容                                                                            |
| -------- | ------------------------------------------------------------------------------- |
| 制定日期 | 2026-10-02                                                                      |
| 实施分支 | `refactor/system-architecture`                                                  |
| 进度基线 | 原方案记录 AO-01 已完成；本计划只拆其余工作，实际完成度须以当前检出代码重新核对 |
| 交付单位 | 原则上每个 AP 任务单独提交一个 PR；跨存储切换和兼容层删除单独评审               |
| 任务状态 | 下表均为“待补齐/待验收”，不表示对应 AO 任务尚无实现                             |

**当前检出基线（2026-10-06，`7aefe7d`）**：代码仍由 `storage.json`、IndexedDB 和事件调度承载主要数据与任务；`src-tauri/Cargo.toml` 没有 SQLite 依赖，`package.json` 没有 `test:desktop-smoke`，仓库也没有桌面 CI workflow。原方案第 10 节和本计划第 5 节记录的是其他实施阶段的历史证据，不能直接当作当前检出代码的完成证明。每个任务启动时先核对代码和前置任务提交；历史实现若已存在，只需补齐本任务的独立验证证据，不重复实现。

本轮继续使用应用本地配置保存密码、Token 和备份密钥，不引入 Keyring。Cookie 保持独立明文存储、默认不进入备份。首版任务执行依赖业务 WebView 存活；窗口关闭后常驻执行不在本计划范围内。

## 3. 独立任务

### A. 可信边界

**2026-10-07 当前结论：AP-01～AP-05 的本地实现与验收已完成。** 用户确认只支持 macOS，并要求在没有外部隔离账号时先完成全部本地工作，因此 Windows/Linux 不属于本轮验收范围；外部账号服务保留为后续验收。完整门禁通过：前端 40 文件 154 项、Rust 44 项、Clippy、格式/架构/诊断检查及 macOS debug 构建；真实双 WebView 竞争、应用释放重建与正常关闭通过。详见 [阶段 A 本地验收结论](./acceptance/AP-A-local.md)。本结论替代第 5 节较早的进行中记录，不代表阶段 B/C/D 已实施。

#### AP-01 补全 IPC 类型与错误契约

- **范围**：以 Rust DTO 为源覆盖剩余 IPC 输入/输出，统一非 storage 命令的稳定错误码、关联 ID 和前端映射；保留已冻结的应用协议。
- **交付**：生成的 TypeScript 契约、集中映射和生成漂移检查。仅复用当前代码中确实存在的命令契约；后续 AP 新增命令时须更新生成源并通过同一漂移检查。
- **验收**：跨层业务判断不解析错误文本；未知输入在 Rust 边界拒绝；生成文件漂移使检查失败；测试覆盖至少一个非 storage 失败调用链。

#### AP-02 收口配置与 metadata 写入、冲突处理

- **范围**：盘点仍能整体写回 config/metadata 的生产入口，改为实体或字段命令；保存使用旧值或 `expectedRevision` 条件提交，冲突时重读并提供合并/重试反馈。
- **交付**：唯一业务写入入口清单、当前 JSON 存储的条件提交操作和设置界面冲突处理。SQLite 条件提交由 AP-06 沿用相同契约实现，下载历史 `saveIfUnchanged` 由 AP-07 实现。
- **验收**：UI 与后台同时改不同字段时两者都保留；同字段冲突不会静默覆盖；写入失败不更新 Pinia 为已提交状态；代码搜索和边界测试找不到可绕过的新整体写路径。

#### AP-03 启动、窗口重建与异步释放

- **范围**：让 `bootstrapApp()` 显式等待可注册的启动阶段和缓存准备；`AppContext.dispose()` 异步停止领取、取消监听并交还租约，覆盖启动失败、HMR 和重复启动。迁移、恢复和持久 worker 由其所属后续 AP 注册阶段并各自验收，AP-03 用可控替身验证等待与释放协议。
- **交付**：可重复调用的启动/释放流程、失败诊断状态和生命周期测试。
- **验收**：业务 UI 不会在必要恢复前挂载；失败后重试不留下旧监听或 worker；跨窗口重建和正常退出等待释放完成；关键读取失败不会被当成空数据继续写入。

#### AP-04 敏感字段访问、删除与诊断脱敏

- **范围**：将密码、Token、备份密钥的保存/读取/删除统一到实体配置操作；补齐当前 JSON 配置的实体删除、列表 DTO、日志及第三方调试入口的裁剪。JSON 到 SQLite 的实际搬迁由 AP-06 验证，AP-04 固定字段与访问契约供其复用。
- **交付**：敏感字段清单及访问约束、当前配置写入失败夹具、列表/日志/备份泄漏回归测试。
- **验收**：当前配置改写失败保留原值；删除实体不会留下其本地凭据；现有普通缓存、日志和默认备份无明文；设置编辑仍可按 ID 读取现有值，运行不依赖 Keyring。SQLite 搬迁与持久任务 payload 分别由 AP-06、AP-09 验收。

#### AP-05 HTTP 资源身份与传输策略收口

- **范围**：补全 social、多域站点及公共 API 的已登记 origin；将资源 ID、连接地址、DNS/代理、重定向、认证头和响应大小策略落实到 reqwest、macOS curl 与文件下载路径。
- **交付**：统一策略及可诊断拒绝码、两种传输的同一场景夹具、真实服务例外清单。沿用现有 32 MiB 普通响应上限与流式文件下载。
- **验收**：请求不能自报 endpoint 扩权；配置删除后旧资源失效；跨源认证头不传播；私网/代理无法保证策略时明确拒绝；超限、重定向及 DNS 场景在目标平台有测试结果。

### B. 数据与任务

#### AP-06 SQLite 基础、迁移标记与旧源退出

- **范围**：建立 SQLite schema 注册表与根记录 Repository，再逐域实现 config、metadata、revision、用户历史、搜索快照、辅种任务的导入标记和旧 JSON 清理；补齐阶段诊断、未知高版本拒绝及清理中断重入。本 AP 必须交付当前分支缺少的 SQLite 基础，不能只验收迁移标记。
- **交付**：SQLite schema 注册表、根记录 Repository、迁移矩阵（源版本、目标版本、活动读写点、清理条件）与升级夹具。
- **验收**：标记与数据同事务提交；清空后的域不会从旧镜像复活；首次无效数据不改活动库；清理失败可在下次启动重试；高版本/损坏 schema 不被覆盖。

#### AP-07 下载历史及剩余数据域迁移验收

- **范围**：核对 IndexedDB → SQLite 下载历史的生产读写、一次性导入、跨窗口 Web Lock、旧源清理；检查搜索快照、用户历史和辅种任务仍有无活动旧写入。
- **交付**：每域唯一活动写入者清单、迁移及重启测试、隔离应用数据目录启动参数、下载历史真实 WebView 并发验证记录。
- **验收**：导入失败保留 IndexedDB 源；导入完成后空历史不复活；跨窗口读写与首次迁移不交叉覆盖；备份快照读取 SQLite 权威值；旧源残留只作兼容/清理用途。

#### AP-08 Pinia 资源缓存重建与多窗口冲突

- **范围**：站点、下载器、历史及任务等持久数据由用例提交后刷新缓存；进入页面、窗口恢复或广播丢失时以 Repository revision 主动重建。
- **交付**：资源缓存失效协议、冲突提示与定向 UI/集成测试；筛选和弹窗等视图状态仍留在 Pinia。
- **验收**：丢弃一次 BroadcastChannel 通知后重新聚焦能读到最新值；旧 revision 不覆盖新缓存；设置编辑冲突有可操作反馈；业务持久化不由 Pinia 快照决定。

#### AP-09 周期任务迁移与资源并发上限

- **范围**：盘点重下载、自动备份、用户信息刷新等周期任务的旧事件和内存 Map；统一持久队列入队、领取、续租及按资源并发限制。
- **交付**：SQLite 持久队列及 `claim_due`、任务种类/幂等键/资源并发矩阵、旧事件兼容转换及退出条件；自动备份同资源领取限制在本 AP 实现。
- **验收**：事件丢失仍可领取到期任务；重启后不重复创建同一周期任务；同资源并发符合矩阵；未识别 payload 版本明确失败且可诊断；应用释放后不再领取并交还租约。

#### AP-10 不确定任务核对、取消与恢复

- **范围**：补齐远端成功但本地未确认、租约过期、长期 `uncertain`、运行中取消和执行器退出的状态转换及人工处理入口。
- **交付**：各任务类型的远端核对策略、可操作的诊断/重试或确认流程、故障注入测试。
- **验收**：无法确认远端结果时不盲目重推；远端已成功可收敛为成功；取消请求与确认取消区分；进程终止后租约恢复不丢任务或复制凭据到 payload。

### C. 恢复与调用链

#### AP-11 跨存储恢复日志与下载历史补偿

- **范围**：明确 SQLite 主事务、IndexedDB 恢复日志和下载历史镜像的 durable 顺序、条件比较、冲突转人工恢复及旧日志兼容路径。
- **交付**：恢复状态表、每个持久化边界的故障注入夹具与启动补偿实现。
- **验收**：任意阶段中断后启动可继续或有明确人工恢复状态；补偿不覆盖并发的新历史；校验失败发生在清空/写入之前；已完成日志可安全清理。

#### AP-12 Cookie 文件提交、补偿与启动恢复

- **范围**：对显式包含 Cookie 的恢复准备替换文件和恢复前副本；将 Cookie 替换、SQLite 提交及恢复日志阶段关联，启动先处理未完成恢复。
- **交付**：Cookie 原子替换与补偿实现、每阶段进程中断测试、恢复冲突诊断。
- **验收**：数据库与 Cookie 不一致时能继续或回滚且保留补偿资料；恢复未决时不开放业务写入；默认备份/恢复不触碰 Cookie；明文 Cookie 不进入普通日志。

#### AP-13 备份格式、安全选项和旧格式验收

- **范围**：验收 v2 manifest、大小/散列/认证、独立 schema 版本、旧 ZIP 导入、凭据与 Cookie 显式选择、备份密钥排除及 SQLite 一致快照。
- **交付**：格式兼容矩阵、损坏与超限夹具、导出选项测试；现有 AES-GCM/PBKDF2 格式以实际代码为准，不在本任务擅自改写格式。
- **验收**：默认文件无凭据和 Cookie；包含凭据时配置来自同一快照；Cookie 导出时变化会重试或拒绝；解密/校验失败不修改活动数据；旧格式恢复语义明确。

#### AP-14 搜索及站点适配器依赖注入收口

- **范围**：从生产搜索工厂延伸到剩余站点解析与非搜索路径，显式传入 HTTP、设置、时钟和日志；统计并逐项移除站点基类默认 client 的隐式回退。
- **交付**：站点调用路径清单、生产装配测试和可独立运行的用例测试。现有搜索 `getSiteInstance` 注入保持兼容。
- **验收**：生产搜索及代表性非搜索站点调用均实际经过注入端口；用例测试不加载 Vue/Tauri；站点包不反向导入 `entries`。

#### AP-15 下载、备份和账号用例依赖注入收口

- **范围**：补齐下载、备份、登录与账号状态的应用接口和生产装配；专用 WebSocket/WebDAV 通道在各自适配器内声明，不隐藏为通用 HTTP 回退。
- **交付**：用例端口、生产工厂与替身测试，覆盖现有下载器、备份服务及登录流程。
- **验收**：生产调用实际读取当前资源配置；删除/修改配置后新请求使用新值；替身测试不启动 WebView；调用链没有从应用层直接读取 Pinia 或任意 `invoke`。

### D. 收口与发布

#### AP-16 Rust 模块按职责拆分

- **范围**：将 HTTP 策略与传输、登录/Cookie、Repository、任务调度和 IPC 命令从混合模块中拆出，保持外部命令与行为兼容。
- **交付**：职责明确的 Rust 模块、共享策略测试及必要的内部服务接口。
- **验收**：reqwest/curl 仍共用授权判定；无需 WebView 即可测试核心服务；现有 Rust 测试和本 AP 的桌面定向用例通过；本任务不混入存储格式切换。

#### AP-17 删除旧入口与兼容写路径

- **范围**：逐一删除已无调用的整体存储消息、导入副作用注册、旧调度事件驱动、默认 HTTP client 和失效例外；保留仍需读取旧版本数据的受控导入器。
- **交付**：删除清单及每项调用搜索/运行证据、更新的架构边界规则。
- **验收**：生产只有新写入/领取路径；旧数据仍能导入；公开命令缺实现时启动失败；构建产物不含已退役入口。

#### AP-18 完成脱敏运维诊断与架构门禁

- **范围**：将逐域迁移阶段、任务积压、恢复日志、缓存 revision 和 HTTP 拒绝原因整合到现有诊断；完善 AST 边界规则并删过期白名单。
- **交付**：只读诊断 DTO、脱敏测试和本地/CI 一致的架构检查。
- **验收**：诊断不返回历史、Cookie、凭据或恢复镜像 payload；人工引入反向依赖或已禁入口会失败；故障时可按 ID/状态定位阶段。

#### AP-19 跨平台 CI 和服务冒烟

- **范围**：在 macOS、Windows、Linux runner 实际执行现有桌面验证和适用的打包目标；补齐平台特有的 HTTP、文件、WebView 与服务适配冒烟记录。
- **交付**：CI 运行链接/产物及失败修复、服务/平台矩阵。打包目标以各平台实际配置为准。
- **验收**：三平台的构建和关键测试有可复核结果；Windows/Linux 安装包只有在实际生成并验证后标记通过；差异和未覆盖服务明确记录。

#### AP-20 真实 GUI 迁移、并发与恢复演练

- **范围**：使用旧版数据在真实 GUI 进行升级、跨窗口并发、任务重启、备份导出/导入及 Cookie/SQLite 分阶段故障演练。
