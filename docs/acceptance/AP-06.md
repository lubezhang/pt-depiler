## 实现与迁移矩阵

生产 Tauri setup 在创建 Cookie 服务、调度器与验收窗口前打开 `storage.sqlite3`，完成数据导入。失败直接阻断启动。存储 IPC 与 HTTP 授权读取统一使用 SQLite；不再读取或写回 JSON 活动镜像。

SQLite schema v1 注册名称为 `root_records_and_imports`。启动核对连续版本/名称、必需表定义、完整性、导入版本与已保存记录结构；高版本、损坏数据库或被改写的 schema 被拒绝。首次创建文件权限为 `0600`，使用 FULL 同步与 SQLite 默认回滚日志；本 AP 不启用 WAL。IPC 数据库工作进入 blocking pool，同一连接由 Mutex 串行访问，比较与写入使用 `BEGIN IMMEDIATE`，也能拒绝另一连接下的旧快照。

| 数据域               | 源版本                            | 目标版本 / 载体                  | 唯一活动读写点                                   | 旧源清理条件               |
| -------------------- | --------------------------------- | -------------------------------- | ------------------------------------------------ | -------------------------- |
| config               | 无版本 JSON（0）                  | SQLite schema 1，根记录 JSON     | Database + 条件 storage IPC                      | 导入与完成标记已提交       |
| metadata             | 无版本 JSON（0）                  | SQLite schema 1，根记录 JSON     | Database + 条件 storage IPC；HTTP 授权只读同一值 | 同上                       |
| revision             | 旧 `__metadataRevision`（若存在） | SQLite schema 1，独立根记录      | metadata 变化时在同事务递增                      | 同上；后续不重建 JSON 镜像 |
| userInfo             | 无版本 JSON（0）                  | SQLite schema 1，版本化集合 JSON | Database + storage IPC                           | 同上                       |
| searchResultSnapshot | 无版本 JSON（0）                  | SQLite schema 1，版本化集合 JSON | Database + storage IPC                           | 同上                       |
| keepUploadTask       | 无版本 JSON（0）                  | SQLite schema 1，版本化集合 JSON | Database + storage IPC                           | 同上                       |

五个业务域和 revision 的首次导入在一个事务中写入数据与六个 `domain_imports` 标记；没有旧记录的域也写标记。已标记域不重读旧源，已有 SQLite 记录优先于旧源，空对象也属于权威值。源 JSON 为对象，集合/历史按现有结构校验，revision 限制为 JavaScript 安全整数；凭据保持原值，不引入 Keyring。

提交后原子清理 JSON 中这六个字段，保留无关字段。清理失败不会撤销已完成的数据迁移：诊断返回 `cleanupPending`，下次启动重试；期间读写仍只有 SQLite。损坏的已迁移旧文件保持原样供人工处理，不会覆盖活动库。`get_storage_status` 为生成的只读 DTO，返回 schema、metadata revision、逐域导入与清理状态，不返回凭据或历史 payload。

本 AP 先建立根记录 Repository。历史、快照、辅种集合暂以版本化 JSON 承载，实体/分页接口与剩余旧整体业务写入口的收口由 AP-07 及后续任务处理；下载历史仍在 IndexedDB，持久队列尚未实施。


脱敏证据为 `AP-06-gui-new.json`、`AP-06-gui-legacy.json`、`AP-06-gui-restart.json` 与 `AP-06-gui-storage.json`。这些文件仅含断言结果、域名/计数/版本，不包含数据库或配置快照。运行中的数据只存在于上述隔离目录，不使用真实用户数据。

## 回滚边界与剩余验收

SQLite 提交后旧 JSON 已退出活动存储，不能直接把旧二进制启动当作回滚。回滚前保全数据库、可能的日志文件和 Cookie；从一致 SQLite 快照导出旧格式配置，再在隔离目录验证旧程序，确认后才切换。不可删除当前数据库后期待残留 JSON 自动恢复。

SQL 故障注入和真实正常关闭/重启已有证据；强杀进程、跨存储备份/Cookie 恢复演练属于 AP-11/12/20。本次没有执行 Windows/Linux、发布包签名、公证或外部服务验收。AP-07～AP-10 尚未实施，阶段 B 不据此整体结项。
