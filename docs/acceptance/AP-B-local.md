# 阶段 B 本地实现与验收记录

日期：2026-10-08。环境：macOS arm64、隔离的 debug 应用数据目录。对应 AP-06～AP-10。阶段 B 的外部数据与服务验收尚未完成，本记录不宣称整体结项。

## 实现状态

| 任务 | 本地实现 |
| --- | --- |
| AP-06 | Rust Repository 唯一写入 `app-state.json`；版本、revision、操作 ID 与逐域导入标记同文件原子替换。稳定锁文件阻断第二进程。旧 `storage.json` 只读导入，目标文件优先；空域不从旧镜像复活。旧 `storage.sqlite3` 存在且目标文件未建立时拒绝首次导入并保留原文件。重启校验后清理 JSON 根域。损坏、高版本、容量超限和同步后提交不确定均拒绝继续盲写。 |
| AP-07 | 下载历史迁入同一文件；主窗口持有旧 IndexedDB 导入权，辅助窗口等待统一文件的迁移标记。主窗口用 Web Lock 串行导出，Rust 校验唯一 ID、状态与容量并提交完成标记。业务读写、条件保存和备份历史读取使用 Rust；旧 IndexedDB 于后续启动清理。上限为 50,000 条且整个文件不超过 32 MiB。 |
| AP-08 | 配置与 metadata 从同一 revision 快照重建 Pinia 已提交缓存；窗口聚焦、可见性恢复和广播触发刷新。下载历史及任务页聚焦后主动读取 Repository，过期的历史列表响应不覆盖新请求。 |
| AP-09 | 周期用户信息、按备份服务的自动备份及延迟重下载改为统一文件持久任务。入队、幂等 ID、资源单并发领取、租约与回执同次提交；事件和待重下载内存 Map 已退出权威路径。统一文件中的任务状态和幂等信息在重启后保留。 |
| AP-10 | 租约过期或执行器释放的任务转 `uncertain`，不自动重推。自动备份每周期持久保存稳定文件名；执行前与人工核对均查询远端同名文件，找到后条件更新备份时间并收敛成功，查询失败或结果不明时不自动上传。旧任务缺少身份且可能已执行时留待人工处理，用户明确重试时才分配新身份。下载历史已完成的重下载任务可直接收敛；其余不确定结果人工处理。设置页提供核对、重试与确认操作；诊断不返回凭据 payload。 |

## 证据

- Rust `ap_06`、`ap_07`、`ap_09`、`ap_10` 定向测试覆盖旧 JSON 导入、SQLite 旧文件拒绝与保留、空域、争锁、条件保存、容量拒写、资源并发、租约到期及取消。
- 5,000 条、每条约 1 KiB 的历史夹具：统一文件 5,413,319 字节；首次导入 164 ms、一次完整文件更新 159 ms；测试进程峰值 43,810,816 字节。本机单次测量，仅用于当前上限的工程基线。
- `pnpm verify:desktop` 退出码 0：前端 41 文件、154 项及 Rust 56 项通过；TypeScript、格式、架构、诊断、Clippy、Vite 和 macOS debug 二进制构建通过。
- 移除 SQLite 导入后重新执行 `pnpm verify:desktop`，退出码 0：前端 154 项、Rust 54 项、Clippy 及 macOS debug 构建通过。恢复原锁定依赖版本后，`cargo test --locked --offline ... ap_06` 的 4 项测试通过；旧文件拒绝与保留、已有统一文件优先均有断言。
- 新增首次下载历史迁移并发与失败重试测试；`pnpm test` 现为前端 42 文件、156 项通过，`pnpm check` 通过。测试验证只导入一次、提交标记后清理旧源，以及导入失败后保留旧源并可重试；真实双 WebView 首次导入仍待演练。
- 隔离 debug GUI 新安装、旧 JSON 升级及同目录重启均通过双 WebView 配置冲突与释放重建；旧 JSON 重启后只剩无关字段。双 WebView 下载历史旧基线保存返回 `STORAGE_CONFLICT`，已提交记录保持权威。脱敏断言见 [AP-B-gui.json](./AP-B-gui.json)，不包含配置或历史正文。
- macOS debug 的 `PTD_E2E_DATA_DIR` 现同时隔离 Rust 文件和 WKWebView 数据存储标识；隔离修正后的 GUI 夹具使用独立 WebView 数据存储，生产数据存储标识不变。
- 隔离修正前的一次 debug GUI 运行曾从默认开发 WebView 的 IndexedDB 导入 6 条历史，并在后续重启清理旧表。6 条经 `publicDownloadHistory` 裁剪的记录保存在该次隔离 `app-state.json`；已用一次性恢复程序按 ID 仅补回缺失记录，结果为来源 6 条、补回 6 条。一次性入口已移除。旧记录的未保留字段无法证明可恢复为原始字节。
- 另用专用 Vite 端口和隔离目录验证首次下载历史迁移：预置 1 条旧历史，注入导入失败后源记录及未完成标记保持；双 WebView 同时启动时主窗口旧源为 1 条、辅助窗口为 0 条，最终统一文件为 1 条，旧源在提交后清理。默认调试来源在演练前后均为 6 条。旧 SQLite 文件阻断隔离启动且原文件未变化，无 `app-state.json` 生成。脱敏结果见 [AP-B-migration-gui.json](./AP-B-migration-gui.json)。
- 自动化新增目录同步失败后核对、旧 JSON 清理重试、未知任务版本、领取提交失败、旧备份任务身份迁移、远端同名备份收敛及条件更新时间戳测试。
- 备份核对定向测试覆盖三种结果：远端存在同名文件时条件更新时间戳并收敛成功；远端文件缺失时保持 `uncertain`；远端列表查询失败时保持 `uncertain` 且不自动重推。
- 本轮 `pnpm verify:desktop` 退出码 0：前端 43 文件、162 项及 Rust 60 项测试通过；格式、类型、架构、诊断、Clippy、Vite 和 macOS debug 二进制构建通过。此后对备份成功时间写入做了同函数收敛，并补跑类型、备份及调度定向测试、Vite 构建；旧任务人工重试身份补齐的 Rust 定向测试也通过。

## 剩余验收

- 对实际下载历史规模再测文件大小、写入尾延迟和内存峰值，并据此复核 32 MiB / 50,000 条上限；当前 5,000 条夹具仅是本机工程基线。
- 远端下载器、备份服务的真实成功但本地未确认场景仍需服务侧核对；本地模拟已覆盖同名备份存在、缺失和查询失败。没有可用的实际服务凭据与可控中断环境，不能将此项标为实测通过。
