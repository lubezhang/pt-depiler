## 目标与范围

目标是让 Tauri 桌面端的核心网络流程可验证、登录态可安全持久化，并使当前范围内的 macOS 与 Linux 遵守一致的请求契约。

本计划覆盖：

- Axios 到 Tauri IPC 的请求协议兼容。
- Rust HTTP 传输、重定向、Cookie 和 Cloudflare 重试。
- Cookie 安全持久化与应用重启恢复。
- 站点登录、搜索、种子下载、下载器和备份流程验收。
- 桌面端自动化测试和 CI 构建门禁。

OTP、WebAuthn 和复杂 SSO 暂不自动处理，但必须提供明确提示或替代登录路径。

## 关键风险

### 1. Cookie 仅保存在内存

`src-tauri/src/state.rs` 使用 `CookieStore::default()` 初始化 Cookie Store，没有启动加载或变更落盘逻辑。应用重启后登录态会丢失。

### 2. Axios 请求语义不完整

`src/extends/axios/tauriAdapter.ts` 是全局 Axios 适配边界，当前将 `FormData` 转换为 `[object FormData]`，导致 multipart 请求不可用。受影响功能包括 qBittorrent、Synology Download Station、Flood、ruTorrent、uTorrent、Google Drive 和 OWSS。

查询参数的数组、嵌套对象和 `paramsSerializer`，以及取消、超时、错误对象和二进制响应也需要契约测试。

### 3. macOS 传输行为存在分叉

macOS 使用 `launchctl + curl` 兼容路径，Linux 使用 `reqwest`。原 curl 路径会丢失 Cookie 的 Domain、Path 和 Expires 语义，重定向链中的 Cookie 也可能关联到错误 URL。`--location` 与显式 `--request` 的组合还可能改变 POST 重定向行为。

### 4. 缺少桌面端质量门禁

当前 GitHub Actions 主要面向浏览器扩展，没有 Tauri 多平台构建矩阵；构建成功也没有覆盖登录、Cookie、multipart、重定向和种子二进制完整性。

## 执行阶段

### Phase 1：建立 HTTP 契约测试

目标：先稳定复现已知问题，再修改全局网络层。

任务：

- 增加仅监听本机随机端口的 HTTP 测试服务。
- 覆盖请求回显、multipart、二进制、延迟、重复响应头和重定向。
- 将 `ptd_fetch` 的核心逻辑从 `tauri::State` 中提取为可直接测试的函数。
- 从 `tauriAdapter.ts` 提取 URL、请求体、响应和错误处理纯函数。
- 引入 TypeScript 测试运行器，并增加统一的桌面端验证脚本。

验收标准：

- 可以稳定复现 FormData、Cookie 持久化和重定向问题。
- 自动化覆盖 302、303、307、308、多个 `Set-Cookie`、超时和二进制响应。
- `pnpm check`、前端测试和 `cargo test` 可以通过单一命令运行。

### Phase 2：修复 Axios 请求兼容

目标：原有 packages 无需增加 Tauri 特判即可正确发送请求。

任务：

- 按 Axios 语义生成最终 URL，支持数组、已有 query 和 `paramsSerializer`。
- 将 IPC 请求体定义为 `none`、`text`、`base64` 等明确类型。
- 正确编码 FormData，保留 boundary、文件名、MIME 类型和二进制内容。
- 保留 URLSearchParams、JSON、Blob、ArrayBuffer、字符串和空请求体语义。
- 保持 `validateStatus`、最终 URL、响应头、错误对象和 `responseType` 兼容。
- AbortSignal 和 CancelToken 必须通知 Rust 终止正在执行的 reqwest/curl 请求，并处理取消早于后端注册的竞态。
- 接通或删除未使用的 `invalidateHostMapCache`。

验收标准：

- qBittorrent 添加种子的 FormData 内容和文件名正确。
- Synology、Flood、ruTorrent、uTorrent、Google Drive、OWSS 通过请求回显测试。
- 登录表单不发生双重编码。
- 下载种子的 SHA-256 与服务端原始文件一致。

### Phase 3：实现 Cookie 安全持久化

目标：Cookie 正确匹配请求，并在应用重启后安全恢复。

任务：

- 使用 Tauri 应用数据目录保存 Cookie Store。
- 使用系统安全存储管理加密密钥，对 Cookie 文件进行认证加密；不允许静默回退到明文。
- 启动时加载并清理过期 Cookie，文件损坏时安全回退到空 Store 并保留诊断信息。
- 在 HTTP 响应、set/remove 和备份恢复后持久化。
- 使用临时文件、`fsync` 和同目录原子替换避免文件截断。
- 串行化并发写入，保证内存状态与磁盘顺序一致。
- 完整保留 Domain、Path、Secure、HttpOnly、SameSite、Expires 和 host-only 属性。
- 日志只记录 Cookie 名称和数量，不记录值。

验收标准：

- 同名不同 Path 的 Cookie 不互相覆盖。
- host-only Cookie 不发送到子域，Domain Cookie 只发送到合法域。
- 删除 Cookie 后重启不会恢复。
- 模拟写盘中断后旧文件仍可读取。
- 应用重启后无需重新登录，且磁盘中无法检索到 Cookie 明文。

### Phase 4：统一 HTTP 传输行为

目标：`reqwest` 与 macOS 兼容路径遵守同一套请求、重定向和 Cookie 契约。

任务：

- 复现并定位 macOS `reqwest` 收到 Cloudflare 异常响应的根因。
- 默认使用 `reqwest`，curl 仅作为命中明确条件后的兼容路径。
- curl 使用标准 Cookie Jar 输入输出，保留完整 Cookie 属性。
- 按重定向链的实际 URL 处理 `Set-Cookie`。
- 分别验证 301、302、303、307、308 的请求方法和请求体行为。
- 在 Cookie 处理前保留重复响应头。
- 对 curl 子进程增加可执行文件检查、超时、stderr 限长和临时文件清理。
- Cloudflare 自动重试默认只用于幂等请求，防止 POST 重复提交。
- 正式日志默认关闭响应正文预览，并设置大小上限和轮转。

验收标准：

- 两套传输通过同一组 HTTP 契约测试。
- POST 不会因重定向或 Cloudflare 重试意外重复提交。
- macOS 不依赖未声明的机器环境即可稳定请求。
- Linux 构建不引用 macOS 专用实现。

### Phase 5：真实工作流与 CI 验收

目标：证明网络基础设施可以支撑主要产品流程，并阻止后续回归。

任务：

- 为 NexusPHP、Unit3D、隐藏字段、相对 action、remember 和验证码增加登录 HTML fixture。
- 登录结果同时校验最终 URL、站点接口和页面状态，不能只依赖 Cookie 数量。
- 登录失败后刷新验证码和表单 token。
- 确保密码在成功、失败、关闭弹窗和组件卸载后都不进入持久状态或日志。
- 提供应用内真实站点登录窗口，并将原生 WebView 的 HttpOnly Cookie 安全同步到统一 Cookie Store 后验证登录态。
- 新增 macOS、Linux Tauri 构建矩阵。
- CI 执行格式检查、类型检查、前端测试、Rust 测试、前端构建和 Tauri 构建。

真实冒烟矩阵：

| 场景          | 最低覆盖                       | 验收结果                         |
| ------------- | ------------------------------ | -------------------------------- |
| NexusPHP 登录 | 1 个无验证码、1 个有验证码站点 | 登录、刷新、重启后均有效         |
| Unit3D 登录   | 1 个站点                       | 登录后用户信息可刷新             |
| 搜索          | 至少 3 个已登录站点            | 聚合结果正常，无跨站 Cookie 泄漏 |
| 种子下载      | 至少 2 种站点 schema           | 文件散列一致                     |
| 下载器        | qBittorrent 和另 1 个客户端    | 测试连接与推送成功               |
| 备份          | WebDAV 或当前使用的远程服务    | 上传、下载和恢复成功             |

验收标准：

- 冒烟矩阵全部通过；失败项有明确阻断原因和跟踪任务。
- macOS/Linux PR 构建稳定通过。
- 至少一个平台的安装包在干净系统中可以安装并启动。

## 发布阻断条件

出现以下任一情况，不发布桌面端：

- Cookie 重启后丢失或以明文落盘。
- FormData、URL 编码或二进制种子存在失败用例。
- POST 可能被自动重复提交。
- macOS curl 与 Linux reqwest 的 Cookie 或重定向结果不一致。
- 桌面端测试为空，或 Tauri 构建未进入 CI。
- 日志包含密码、Cookie 值、Authorization 或带敏感查询参数的完整 URL。

## 完成定义

所有阶段验收通过，真实冒烟矩阵无阻断项，macOS/Linux CI 稳定，应用重启后登录态与核心工作流均正常，方可认为当前范围内的 Tauri 网络与认证层达到可发布状态。Windows 在重新纳入范围后需单独补齐同等级验收。
