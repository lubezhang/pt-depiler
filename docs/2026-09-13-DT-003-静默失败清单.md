# DT-003 静默失败清单

DT-003 将关键路径的空 `catch` 或未处理 Promise 改为可观察的失败出口。诊断日志只记录操作名称，原始异常仅输出到本地控制台，避免将 Cookie、Token、下载 URL 等任意异常内容持久化。

| 位置                                      | 原风险                                                                     | 修复后的错误去向                                                                             |
| ----------------------------------------- | -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `src/entries/options/service/index.ts`    | 启动用户信息修复失败被空 `catch` 忽略。                                    | `fixAllStoredUserInfo()` 的异常传到启动入口，并输出本地控制台诊断。                          |
| `src/entries/background/utils/fixer.ts`   | 存储读写失败在函数内部仅输出后被吞掉，调用方无法感知。                     | 移除内部吞错，由启动入口统一处理。                                                           |
| `src/entries/offscreen/utils/download.ts` | 下载请求配置、调度、下载器诊断和状态写入失败可能被忽略或伪装成功。         | 下载任务返回失败结果，状态写入失败向调用方传播；异步诊断失败输出控制台并写入无敏感操作日志。 |
| `src/entries/background/utils/alarms.ts`  | 自动刷新、自动备份、延迟重试和 scheduler listener 的失败可能没有错误出口。 | 失败写入无敏感后台诊断并输出控制台；重试任务将下载历史设为 `failed`，调度失败从调用链传播。  |
| `src-tauri/src/scheduler.rs`              | Rust scheduler 的 event emit 结果被丢弃。                                  | emit 失败仅通过 `eprintln!` 输出 stderr 本地 scheduler 诊断。                                |

测试覆盖短延迟与 Rust 事件重试失败、调度 invoke 失败、下载状态持久化失败、自动备份失败、自动刷新站点失败、listener 注册失败，以及启动存储读取失败。

Rust scheduler 的 event emit 失败目前不会持久化任务状态，也不会在下次启动时恢复；持久化任务状态机与恢复机制由 DT-021、DT-022 负责。
