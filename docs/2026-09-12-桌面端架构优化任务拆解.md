## 3. P0：基线修复与防回归

### DT-001 修复消息协议注册缺口

- **目标**：确保所有公开消息协议都有对应实现，消除运行时才暴露的 handler 缺失。
- **范围**：为 `setDownloadHistoryStatus` 注册 handler；枚举 `ProtocolMap` 与注册表；增加协议完整性测试。
- **交付物**：状态更新实现、注册覆盖测试、缺失 handler 时可定位的错误信息。
- **验收**：下载重试失败后历史记录最终为 `failed`；测试能在任一公开 handler 缺失时失败。
- **非目标**：本任务不替换整个 `messages.ts`。

### DT-002 修复 Pinia 持久化生命周期与错误传播

- **目标**：消除 `$dispose` 覆盖后潜在递归，并让存储失败对调用方可见。
- **范围**：保存原始 `$dispose` 引用；重构 `$save()` 返回值和异常处理；覆盖恢复、保存、释放测试。
- **交付物**：无递归的释放逻辑、明确的保存错误、持久化插件单元测试。
- **验收**：调用 `$dispose()` 只执行一次原始释放；模拟 Tauri Store 写入失败时调用方收到结构化错误。
- **非目标**：不在本任务中迁移 Pinia 数据载体。

### DT-003 清理关键路径静默失败

- **目标**：关键持久化、任务调度和状态更新错误不再被空 `catch` 吞掉。
- **范围**：先覆盖启动、存储、下载状态、自动备份、任务调度；业务解析中的容错 `catch` 需说明理由并记录 debug 信息。
- **交付物**：静默失败清单、错误上报路径、针对失败分支的测试。
- **验收**：关键路径不存在空 `catch` 或仅 `.catch()`；失败会进入 UI、任务状态或本地诊断日志之一。
- **非目标**：不要求一次清除所有站点解析器中的容错逻辑。

### DT-004 移除未使用的桌面插件与权限

- **目标**：缩小主窗口权限和依赖面。
- **范围**：验证 notification、global-shortcut 的真实调用；无调用时移除 Cargo 依赖、插件初始化和 capability。
- **交付物**：精简后的 `Cargo.toml`、Tauri 初始化代码和 capability 配置。
- **验收**：Rust 编译与桌面启动通过；产物不再包含确认无用的插件权限。
- **非目标**：CSP 和登录窗口权限拆分由 DT-016 处理。

### DT-005 对齐前端依赖版本并固化桌面验证基线

- **目标**：得到可信、可重复的重构前基线。
- **范围**：确认 Vite、Vue、Vue Router、TypeScript 的受支持组合；升级或降级冲突版本；执行并记录 `verify:desktop`。
- **交付物**：锁定后的依赖、必要的兼容修改、基线测试记录。
- **验收**：格式、类型检查、前端测试、前端构建、Rust fmt/clippy/test 和 Tauri debug build 全部通过。
- **非目标**：不引入新的应用架构模块。

### DT-006 建立架构边界与产物静态检查

- **目标**：迁移期间阻止新增反向依赖和扩展时代入口。
- **范围**：检查 `packages/domain` 不导入 `entries`、Vue、Pinia、Tauri；检查空 `catch`、side-effect import、全局 monkey patch；检查产物不包含浏览器扩展入口。
- **交付物**：可在本地和 CI 运行的边界检查命令及失败示例测试。
- **验收**：人为加入一条违规依赖或 `manifest.json` 后门禁失败；现有例外具有明确白名单和删除任务。
- **非目标**：不以静态检查代替运行时和集成测试。

## 4. P1：应用边界与安全边界

### DT-007 建立统一错误模型和结构化日志契约

- **目标**：为后续 TypeScript/Rust 迁移提供稳定的错误和诊断语义。
- **范围**：定义错误分类、稳定错误码、IPC envelope、脱敏字段和 `operationId/resourceId/taskId` 关联字段。
- **交付物**：两端错误 DTO、转换器、脱敏日志工具和契约 fixture。
- **验收**：业务错误无需解析任意字符串；日志测试证明 Cookie、密码、Token 和认证 URL 不会落盘。
- **非目标**：不要求一次替换所有旧错误文本。

### DT-008 实现显式 `bootstrapApp()` 启动流程

- **目标**：替代依赖 import 副作用的半隐式启动。
- **范围**：创建基础设施适配器、运行迁移、注册服务、验证协议覆盖、恢复任务、挂载 Vue；实现失败诊断页和 `dispose()`。
- **交付物**：`AppContext`、`bootstrapApp()`、启动状态 UI、监听器取消订阅机制。
- **验收**：初始化任一步失败时不挂载业务 UI；窗口重建或退出时监听器被释放；启动流程有顺序测试。
- **非目标**：首版可继续通过兼容适配器调用旧 handler。

### DT-009 建立类型化 Command/Query/Event 总线

- **目标**：用封闭协议取代可任意扩展的字符串消息表。
- **范围**：定义 Command、Query、Event 映射；冻结注册表；为旧 `sendMessage()` 建兼容转发；校验序列化边界。
- **交付物**：类型化总线、旧协议适配器、注册完整性和 DTO 测试。
- **验收**：未声明命令无法编译或注册；公开命令缺失实现时启动失败；不允许函数、类实例和 DOM 穿过协议层。
- **非目标**：不在一个 PR 内迁移全部用例。

### DT-010 迁移搜索用例作为应用层样板

- **目标**：验证无副作用读用例的目标分层。
- **范围**：将搜索编排移入 `application/search`；通过端口注入站点工厂、HTTP、配置读取和日志；保留现有 UI 行为。
- **交付物**：搜索 Query/Use Case、内存端口测试、旧入口兼容适配。
- **验收**：用例测试不启动 Vue 或 Tauri；现有搜索 UI 与错误状态保持兼容；领域包不新增 `entries` 依赖。
- **非目标**：不改写 296 个站点定义。

### DT-011 迁移下载历史用例作为写操作样板

- **目标**：验证 Command、事件、并发写入和错误传播路径。
- **范围**：迁移读取、更新状态、删除和清空历史；发布 `DownloadStatusChanged`；首版继续适配旧存储。
- **交付物**：下载历史 Command/Query、事件通知、内存 Repository 测试。
- **验收**：状态更新成功后 UI 从事件或刷新获得一致结果；失败不产生虚假成功状态；重复操作行为明确。
- **非目标**：SQLite 数据迁移由 DT-019 完成。

### DT-012 定义 Repository、SecretStore 和 HttpClient 端口

- **目标**：稳定应用层与平台实现之间的边界。
- **范围**：定义受约束的 Repository、SecretReader/Writer、HttpClient、TaskScheduler、Clock、Logger 接口及测试替身。
- **交付物**：`domain/ports` 类型、内存实现、依赖方向测试。
- **验收**：应用用例可完全通过端口运行；端口不暴露原始 SQL、任意 `invoke` 或“列出全部明文 Secret”。
- **非目标**：具体平台实现分别由后续任务完成。

### DT-013 实现 Rust Keyring SecretStore

- **目标**：为下载器、站点和备份凭据提供不落普通配置文件的安全存储。
- **范围**：实现 `{category}/{entityId}/{field}` 键规则、增删改查受控命令、能力探测、待清理队列和 Linux 不可用诊断。
- **交付物**：Rust SecretStore 服务、窄 IPC、平台集成测试。
- **验收**：前端只能获知 `configured` 状态；日志不包含明文；Keyring 不可用时明确失败且不回退到明文。
- **非目标**：旧数据正式迁移在 DT-018 中执行。

### DT-014 实现 HTTP 资源身份与动态访问策略

- **目标**：允许用户配置站点和局域网服务，同时限制 SSRF 与凭据跨源泄漏。
- **范围**：实现资源身份、endpoint 登记、协议和方法限制、敏感头托管、逐跳重定向校验、DNS/私网策略、响应体上限。
- **交付物**：`HttpPolicy`、策略化 transport、拒绝原因和安全测试矩阵。
- **验收**：非法协议、未登记 endpoint、站点访问私网、跨源转发认证头均被拒绝；登记的局域网下载器正常工作。
- **非目标**：不使用固定域名白名单，不重写所有领域 HTTP 调用。

### DT-015 移除全局 Axios Adapter 并迁移下载器、备份客户端

- **目标**：消除 `axios.defaults.adapter` 全局修改，让每个请求携带明确资源身份。
- **范围**：实现显式 HttpClient；优先迁移下载器和备份服务；保留受控兼容客户端供未迁移模块使用。
- **交付物**：资源级客户端工厂、迁移后的调用方、兼容层使用统计。
- **验收**：应用启动不再设置全局 Axios Adapter；下载器与备份请求全部经过 DT-014 策略；行为回归测试通过。
- **非目标**：剩余站点和社交服务可在 DT-026 前逐步迁移。

### DT-016 启用 CSP 并拆分窗口 capability

- **目标**：限制 WebView 被利用后的平台能力范围。
- **范围**：制定 CSP；分别配置 `main`、`site-login` 和 debug 测试窗口；登录窗口禁用业务 invoke，仅保留导航和 Cookie 同步所需能力。
- **交付物**：CSP、按窗口 capability、登录窗口安全测试。
- **验收**：主流程在 CSP 下正常运行；登录窗口无法调用业务命令；debug 能力不进入 release 产物。
- **非目标**：不改变站点登录产品流程。

## 5. P2：持久化、任务与备份

### DT-017 建立 SQLite、迁移注册表和 Repository IPC

- **目标**：建立 Rust 作为结构化持久化数据唯一所有者的基础。
- **范围**：数据库初始化、`schema_migrations`、事务迁移、版本拒绝策略、revision 并发控制、受约束 Repository 命令。
- **交付物**：数据库模块、首个 schema、迁移框架、Repository 和 IPC 契约测试。
- **验收**：迁移幂等；故障注入不会产生半版本数据库；未知更高版本只读或拒绝写入并给出诊断。
- **非目标**：本任务只建立基础设施，不一次迁移全部业务数据。

### DT-018 迁移 config/metadata 并执行敏感字段迁移

- **目标**：优先统一配置数据，并将明文凭据迁入 Keyring。
- **范围**：迁移普通配置和 metadata；识别下载器、API Token、S3、备份等敏感字段；Keyring 回读成功后以 `secretRef` 替换明文。
- **交付物**：版本化迁移、旧格式兼容读取、迁移前快照、敏感值落盘扫描测试。
- **验收**：真实旧数据副本迁移成功且可重复执行；任一步失败保留旧数据；应用数据目录中无法检索测试 Secret。
- **非目标**：不自动导出 Keyring 中的 Secret。

### DT-019 迁移下载历史、搜索快照和辅种任务

- **目标**：将 IndexedDB/Store 中的结构化业务数据收敛到 SQLite。
- **范围**：按下载历史、搜索快照、辅种任务顺序迁移；实现分页查询、事务写入和 revision 冲突。
- **交付物**：各数据域 Repository、迁移器、真实数据 fixture、只读回退工具。
- **验收**：迁移前后记录数和关键字段一致；中断后重启可继续或安全回滚；一个发布周期保留旧文件只读能力。
- **非目标**：不立即删除旧 Store/IndexedDB 文件。

### DT-020 将 Pinia 收敛为视图状态和资源缓存

- **目标**：消除 Pinia 与 Rust Repository 双数据源。
- **范围**：区分 view store 与 resource store；移除整个 store 自动持久化；资源数据只通过 action 查询和刷新；关闭前 flush 必要批处理。
- **交付物**：重构后的 stores、缓存失效规则、刷新和冲突 UI。
- **验收**：刷新窗口后状态来自 Repository；Pinia 不直接写业务持久化；revision 冲突不会静默覆盖新数据。
- **非目标**：筛选条件、弹窗状态等临时 UI 状态无需落盘。

### DT-021 实现持久化任务状态机与恢复机制

- **目标**：后台任务真相由 Rust 持有，应用退出或崩溃后可恢复。
- **范围**：实现任务表、状态机、`run_at`、attempt、lease、幂等键、脱敏错误和启动恢复。
- **交付物**：Task Repository、Scheduler Service、worker 生命周期和故障注入测试。
- **验收**：过期 `running` lease 可恢复；重复领取不会重复副作用；任务成功与业务状态在同一事务提交。
- **非目标**：不承诺后台执行需要用户交互的登录或验证码流程。

### DT-022 迁移重下载、自动备份和用户信息刷新任务

- **目标**：删除前端定时器和内存 `Map` 对可靠性的依赖。
- **范围**：逐类迁移 `redownload`、`auto_backup`、`refresh_user_info`；定义版本化 payload 和幂等处理器。
- **交付物**：三类任务处理器、旧调度器切换开关、重启恢复测试。
- **验收**：任务执行前强制退出，重启后继续且不重复下载/备份；重试耗尽进入明确失败状态。
- **非目标**：兼容入口可保留到 DT-026。

### DT-023 实现备份格式 v2

- **目标**：提供版本化、可认证且明确区分普通数据和凭据的新备份格式。
- **范围**：定义 manifest；使用 PBKDF2/Argon2id 与 AEAD；每个文件独立 nonce；限制 ZIP 路径、大小和 schema；保留 v1 只读。
- **交付物**：v2 编解码器、格式说明、round-trip/tamper/兼容 fixture。
- **验收**：新版只写 v2；篡改密文、manifest 或文件路径时恢复被拒绝；v1 仍可导入但不再生成。
- **非目标**：默认不导出 SecretStore；凭据导出必须显式选择并设置口令。

### DT-024 实现分阶段恢复、journal 与失败回滚

- **目标**：恢复失败或崩溃后原数据仍可使用。
- **范围**：实现 Validate、Stage、Commit 三阶段；创建恢复点；用 journal 协调 SQLite、Keyring 和 Cookie 文件；提供继续或补偿回滚。
- **交付物**：恢复事务服务、预览和冲突报告、恢复点管理、逐步骤故障测试。
- **验收**：每个恢复步骤注入失败后均可回到一致状态；重启能识别未完成 journal；成功后缓存正确重载。
- **非目标**：不假设跨 SQLite、Keyring、Cookie 文件存在真正的单事务。

## 6. P3：收口与发布

### DT-025 按职责拆分 Rust 平台模块

- **目标**：让平台服务可在不启动 Tauri Runtime 时独立测试。
- **范围**：拆分 HTTP policy/transport/redirect、Cookie Vault、登录窗口、Repository、Secret、Scheduler 和薄 IPC command。
- **交付物**：目标目录结构、普通 Rust 服务接口、模块级测试。
- **验收**：IPC command 不包含复杂业务规则；核心策略测试无需 Tauri Runtime；macOS curl 路径保持条件编译。
- **非目标**：不做仅移动文件、不改变职责边界的机械重命名。

### DT-026 迁移剩余用例并删除扩展时代兼容层

- **目标**：完成新架构调用方覆盖，移除旧消息和 WebExtension 风格边界。
- **范围**：迁移站点、用户信息、下载、备份、社交和辅种用例；删除本地消息兼容路由、旧 Store 写路径、`background/offscreen/webExtPersistence` 旧命名。
- **交付物**：迁移率报告、零引用检查、删除提交和替代模块文档。
- **验收**：`src/packages` 不导入 `src/entries` 或 Tauri；旧消息总线和旧持久化写路径无引用；所有公开用例有类型和测试。
- **非目标**：只有在调用方迁移率达到 100% 后才删除兼容层。

### DT-027 完善跨平台 CI 与真实服务冒烟矩阵

- **目标**：证明架构迁移在支持平台和关键用户路径上可发布。
- **范围**：加入 macOS/Linux 构建、安装后启动；覆盖登录、搜索、下载器推送、备份恢复、重启恢复；补齐 IPC、Keyring、Cookie 和 transport 集成测试。
- **交付物**：CI workflow、平台矩阵、真实服务冒烟脚本和失败诊断产物。
- **验收**：所有门禁稳定通过；至少一个平台完成安装后启动；真实服务矩阵没有阻断项。
- **非目标**：不逐站执行 296 个完整 E2E；站点适配继续使用 schema/definition fixture 分层覆盖。

### DT-028 执行发布迁移演练与兼容层删除门禁

- **目标**：用真实升级路径验证数据、凭据、任务和备份兼容性。
- **范围**：从仍支持的每个历史版本升级；演练中断恢复、降级只读工具、Keyring 不可用、备份回滚；检查磁盘明文和 release 权限。
- **交付物**：发布检查表、迁移演练报告、已知限制和回滚手册。
- **验收**：连续两个发布周期无兼容层回退使用；完成定义全部满足后，才允许删除只读回退工具和旧文件支持。
- **非目标**：不在验证不足时以版本发布压力为由提前删除兼容路径。

## 8. 每个任务的通用完成标准

除任务自身验收条件外，每个任务还必须满足：

1. 变更具备对应层级的自动化测试，失败分支不能只靠人工验证。
2. `pnpm verify:desktop` 全部通过，且生成的 debug 桌面产物能够实际启动并完成基础 UI 冒烟；任一环节失败时不得将任务标记为“已完成”或继续后续任务。
3. 不引入新的 `packages -> entries`、`application -> invoke/IndexedDB/Keyring` 反向依赖。
4. 不新增未解释的空 `catch`、全局 monkey patch 或 import 副作用。
5. 涉及持久化格式时提供升级 fixture、失败回滚和重复执行测试。
6. 涉及 Secret、Cookie、Token 或 Authorization 时提供脱敏和落盘扫描测试。
7. 涉及兼容层时记录新旧路径使用率、切换方式和明确删除条件。
8. 更新相关架构文档、接口契约和发布说明。

## 9. 建议的首轮迭代范围

首轮迭代只执行 `DT-001` 至 `DT-006`。它们解决当前已知缺陷并建立迁移门禁，不改变数据格式，回滚成本最低。完成后再并行推进错误模型、显式启动和端口定义，避免在缺少可靠基线时同时引入应用层、Keyring 和 SQLite 三类变化。
